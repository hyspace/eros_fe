# 007 · 按实际图片尺寸统一缓存键

- 日期：2026-09-19。
- 提交：`1d8a619b145a6649e74691f7e5494fdb79e9a1c4`，与 008 同次集成。
- 分支：`fix/reader-cache-representation`。
- 本次主干合并：`ff57473a0f31ca74cb01d9e83fce9cb13617455a`。

## 为什么改

新日志证明缓存复用已经生效，但仍有此前读过的页面被重新下载：
同一页的地址有时带 `xres=1280`，有时没有这个参数，旧 key 因此分裂为
`_1280` 和空后缀两种形式。

一个采样的 42 页任务中，15 页直接来自阅读缓存；另有 5 页存在上述键差异，
重新走了网络。还有一页在下载握手失败并换源后，才碰巧匹配到早已存在的缓存。
这说明缓存键差异不仅增加流量，也让用户多次暴露于坏节点。

两次传输的字节数相同不足以证明内容完全相同，因此不能简单把所有缺省 `xres`
都当作 1280，或无条件合并不同图片版本。

## 改了什么

- 引入 `ReaderCacheSpec`，对有可信元数据的重采样图使用“页面标识＋实际宽高”
  的版本键，不再依赖 CDN 主机或 URL 是否携带 `xres`。
- 阅读、预加载和普通下载共用 `readReaderImageCache`。
- 兼容旧数字/空后缀键和 URL-MD5 键；旧缓存跨键复用前读取图片自身宽高，
  与当前页面元数据的宽、高都匹配才命中。
- 原图保持独立 `_origin` 键；缺少可信宽高时不猜测版本。
- 恢复任务换成另一个 URL 时，不把旧 URL 的尺寸直接视为新 URL 的证据。
- 常见键直接查找，其他旧后缀用短期共享目录索引，避免逐页遍历整个缓存。
- 诊断区分别名命中和尺寸不符，不再把有效旧缓存误报为未落盘。

## 为什么这样做

缓存身份应代表页面的图片版本，而不是某次网络路由的 URL 拼写。
同时必须守住图片质量边界，不能为了命中率把低分辨率缓存导出成原图。

沿用目录并兼容旧键，让升级前已读的漫画继续受益，不需要清空缓存或迁移数据库。
宽高校验是本次兼容条件，**不是图片内容的密码学哈希证明**。

## 验证与边界

缓存修复阶段 **102 项回归测试**通过，覆盖两种旧键、尺寸/页码/原图区分、
阅读和预加载零网络命中、解析前后命中及诊断脱敏。
与 008 集成后总回归数为 120；安装版本 `1.9.2-private-sni1` 后用户反馈验证成功。

未知旧后缀的共享索引最多存在短暂滞后；它会导致一次保守未命中，而不是读错版本。
没有修改 archive 下载、下载文件格式或两处独立的远程同步/头像异常。

当前实现细节见 [维护指南](reference/download-cache-diagnostics.md)。

# 004 · 保全本地恢复与检查点导出

- 日期：2026-09-16。
- 提交：`66c9d8457d4baec74b2cde7c1d0e4bd897f4d10f`。
- 分支：`feat/local-backup-export`，基于 `8b28e6f5`。
- 状态：**代码只在独立分支；未合入主干，也不在当前主 App 中。**

## 为什么改

此前本地版本中做过恢复/备份相关功能，但代码不能只保存在本机构建目录里。
用户要求把已有改动放到独立分支，避免后续切换主线和更换测试版本时遗失。
这次提交的目标是**保全已有实现**，不是执行一次新的数据恢复。

## 保存了什么

- Android 高级设置中的本地恢复与备份入口，以及恢复 JSON 的检查/导入流程。
- 导入前备份数据库、保留无关新任务、处理冲突和缺页/页数未知的标记。
- 导出当前数据库检查点到下载目录，写入后使用 SHA-256 回读校验。
- 恢复测试模式所需的下载/删除/旁文件写入限制，不能只摘取“导出按钮”。
- 将已锁定的 `crypto 3.0.6` 提升为直接依赖，没有升级其版本。
- `FE_LOCAL_RECOVERY` 和 `FE_RECOVERY_TEST` 在该分支默认关闭。

## 为什么不一起合入

用户决定以后日常只安装自己编译、沿用同一签名的版本，不再为切换官方签名而
卸载迁移。因而先让主干聚焦下载和阅读修复，备份功能需要时再单独整合。

此分支基线较早，下载控制器等文件与新主干存在重叠。以后合并应重新解决冲突和
验证，而不是把旧文件整段覆盖到新主干。

## 验证与边界

历史提交记载：核对了 **11 个恢复文件**与归档源码的一致性，静态分析无错误，
启用功能的 Android ARM64 Dart bundle 可编译。这不表示本次重新执行过设备端
导入/导出或完成新的恢复安全审计。

检查点包含任务、逐页记录、设置和阅读进度，**不包含漫画图片**。虽然导出会处理
画廊登录用户字段，其他设置/远程配置仍可能敏感；检查点绝不能直接提交到 GitHub。
格式也不是官方通用 profile 格式或完整 ZIP 备份。

完整的分支说明已归档为 [文档快照](reference/local-backup-export.md)。
主干收录这份说明，**不代表导出功能代码也被合并**。

# 006 · 有界握手恢复与手动重试

- 日期：2026-09-19。
- 提交：`a11603b5f06cd9d522d8b5a9854de04a78360ee7`。
- 分支：`fix/handshake-recovery`。
- 本次主干合并：`3376f1281497b2a7e8856325212d60bba64253e9`。

## 为什么改

阅读和普通下载遇到握手错误，页面可能长时间等待；失败后还必须能主动重试，
不能把任务变成无法继续的终止状态。原先基于“无网络流量”的整本重启会混淆
缓存命中、慢节点和真正的失败，并放大重复工作。

调查还发现超时配置的毫秒值被当成秒使用，以及部分普通下载按钮误调用
archive 重试方法、把 gid 当归档列表索引的问题。

## 改了什么

- 下载重试改为逐页负责：一次初始尝试加最多三次自动重试，退避 1/2/4 秒。
  真正失败才增加计数；普通瞬时错误第三次失败后尝试带 sourceId 换源。
- 首张、尾张和单页任务也刷新过期地址；每次尝试都保留缓存优先。
- 删除“没有流量就重启整本”的监控。其他页可继续完成，剩余失败页最终使任务
  暂停，保留已完成内容，等待主动恢复。
- UI 区分“重试/继续”“重试未完成页”和“全部重新下载”；普通任务只调用普通
  下载恢复，不进入 archive 重试。
- 修正 Dio 超时单位。阅读/预加载使用独立、可控的传输路径，同时保留既有缓存。
- 增加脱敏的连接阶段、TLS 错误、代理类型、重试预算和暂停事件。

## 为什么这样做

网络失败应局限在相关页面，自动重试应有终点，用户的手动重试又应能获得新的
预算。自动恢复不能拿清空进度、重建已完成行或重新传输整本作为代价。

阅读和预加载也需要有界等待；但仅加超时不能宣称所有底层 socket 一定立即释放。
当时的 isolate 传输实验没有通过验证，因此没有提交或安装那套实验实现。

## 验证与后续

当时 **89 项回归测试**通过，并用负向对照验证能发现普通任务错误路由到
archive 的问题；完成同签名覆盖安装检查。

原始 IO 路径中，Dart 已进入 TLS 且对端完全无响应时的底层 socket 回收限制
仍需保留说明。未通过降低 TLS 版本、扩大证书放行来处理握手错误。

后续重放进一步定位出特定节点的 SNI 相关行为，才加入经过验证、可独立关闭的
原生兼容路径，见 [008](008-temporary-tls-compatibility.md)。这不等同于把当时
被否决的 isolate 实验重新启用。当前预算与诊断见
[维护指南](reference/handshake-recovery.md)。

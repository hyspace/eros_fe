# 普通下载：缓存优先与诊断

## 阅读缓存的图片版本

有些图片地址含 `xres=1280`，换源后同尺寸的地址却不含 `xres`。
旧版以这个参数拼缓存 key，会把同一页拆成 `_1280` 和 `_` 两份。

- 新 key 使用已解析页面的实际宽高：`<encoded href>_resampled_<width>x<height>`，
  不再依赖 CDN 主机或 `xres` 是否存在。
- 阅读、预加载、普通下载使用同一套查找逻辑。
- 兼容原来的数字/空后缀 key 和 URL-MD5 key；跨旧 key 复用时读取图片自身宽高，
  必须与当前页面元数据**宽、高都一致**。同尺寸不等同于内容字节哈希验证。
- 原图继续使用独立的 `_origin` key，绝不从重采样别名取文件。
- 缺少可信宽高时保留旧精确匹配，不猜测缺省分辨率。恢复旧任务若换了 URL，
  不把另一个 URL 的尺寸当成该地址的已知元数据。
- 优先直查常见 key；其他旧分辨率后缀使用 30 秒共享目录索引，避免逐页扫描
  整个缓存。极少数刚写入的未知旧后缀可能等索引刷新后才命中；不会读错版本。
- 不清空缓存、不改下载文件/数据库格式；SAF 和已有自动/手动重试流程保持不变。

## 重试语义

`reDownload` 表示自动补页时需要重新解析下载链接，**不是跳过图片缓存**。
初次下载、自动补页和 403 换链接后都先检查同版本图片缓存。
原图地址尚未知时不拿重采样缓存代替；保留原有解析后的版本选择逻辑。

恢复任务时：

- 合并阅读快照、已有任务记录和内存中最新的图片信息。
- 缩略图或空字段不得覆盖已解析的图片地址、原图地址和换源信息。
- 已完成的数据库记录及文件名不被重新初始化。
- 新解析的图片信息在传输前保存，因此传输失败后仍能重新定位缓存和换源。

## 开启测试版诊断

构建时添加：

```sh
--dart-define=FE_DOWNLOAD_DIAGNOSTICS=true
```

默认关闭。诊断日志独立于普通日志等级，因此 Release 模式下也能记录缓存命中。
日志写入应用自己的日志目录：

- `download-diagnostics.log`
- `download-diagnostics.log.previous.log`

采用 JSON Lines 格式，每份约 1 MiB，仅保留当前及上一份。
写日志失败不会中断下载。

主要事件：

| 事件 | 含义 |
| --- | --- |
| `session_start` | 诊断已启用 |
| `reader_ready` | 阅读／预载采用的缓存键指纹，以及文件是否确实落盘 |
| `task_start` | 任务页数、已完成数及已知图片地址数量 |
| `page_start` | 页码、是否重试、原图／重采样模式、元数据完整性 |
| `cache_not_checked` | 尚无足够元数据定位指定版本的缓存 |
| `cache_miss` | 缓存不存在、读取失败、空文件或非图片 |
| `cache_found` / `cache_saved` | 找到缓存／成功保存到下载目录 |
| `metadata_fetch` / `metadata_resolved` | 获取图片信息及是否尝试换源 |
| `network_start` / `network_complete` | 进入图片传输阶段／传输完成及字节数 |
| `network_error` | 错误类型、HTTP 状态和分类后的 TLS 错误 |
| `page_retry` / `page_retry_exhausted` | 逐页自动重试／本轮预算耗尽 |
| `task_paused_after_errors` / `page_complete` | 失败页保留后暂停／单页完成 |

用相同 `gid`、`page` 和 `key_hash` 关联阅读与下载。
`key_hash` 表示请求的图片版本 key，不是图片内容哈希；`key_type=reader_alias`
表示经过尺寸验证的旧缓存别名。`dimensions_mismatch` 表示缓存存在但尺寸不符；
这种情况按未命中处理。阅读探测也检查别名，不再把旧缓存命中误报为未落盘。
`phase` 区分解析前、解析后的缓存查找；403 等传输失败回到同一套有界恢复流程。
进入传输阶段不保证已发出 TCP/TLS 请求：短时避让会在 adapter 内提前结束，
需要结合 `image_host_avoided` 分析。端点恢复及历史兼容事件见
[端点恢复](image-endpoint-compatibility.md)，不要把流水线事件重复统计成实际下载次数。
网络事件只记录协议、主机和端口，不记录完整 URL、Cookie、图片 token、
书名、文件名或原始错误文本。日志仍包含作品编号和页码，分享前请检查。

## 测试

按项目 README 准备本地示例配置（不要提交真实配置）后：

```sh
flutter test --no-pub test/download
```

包含真实临时缓存文件、实际任务恢复/补页规划和 Executor 调度的 34 页用例：
第 19 页首次传输发生模拟 TLS 错误；其余 33 页已完成；缓存随后就绪时，
自动补页必须完成第 19 页且不再解析页面或联网传图。
测试只替换远端图片信息和传输边界，不访问真实漫画站点。

这些测试验证缓存和恢复逻辑，不代表远端 TLS/代理故障已经修复。

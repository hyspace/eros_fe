# Private Fork 变更记录

这里记录本 fork 相对上游的每次改动：**为什么改、改了什么、为什么选择这种做法、
如何验证，以及当前是否已合入主干**。它既是历史记录，也是后续维护、回退和移除
临时兼容方案时的依据。

上游原有的 `changelog/` 按版本存放发布说明；本目录补充 fork 的逐次设计与实现记录，
不覆盖那套发布记录。

## 当前功能边界

- 普通下载复用缓存、下载失败后的有限自动恢复/手动重试、实际尺寸缓存键均在主干。
- 临时端点兼容层提供两个独立编译开关：
  `FE_IMAGE_FAST_FAILOVER`、`FE_IMAGE_SNI_COMPAT`，目前默认开启。
  它不是全局关闭 SNI，也不是放宽证书验证。
- `feat/local-backup-export` 仍单独保留。主干里有它的变更记录和文档快照，
  **没有它的恢复/导出模块和设置入口**。
- 阅读进度远程同步的空集合异常、论坛头像接口的 403 本轮未修复；不得把它们
  记作 TLS 兼容或缓存修复已经解决的问题。
- 自行编译并沿用既有签名。禁止用卸载、清数据或更换签名来完成日常升级。

## 以后如何补充

每个功能修复或设计调整新增一个顺序编号条目，至少记录：

1. 日期、对应提交/分支、主干状态和影响范围。
2. 用户遇到的问题、可核实的原因；将事实与推断分开。
3. 做了哪些修改，哪些内容明确未改。
4. 设计取舍、没有采用的方案及理由。
5. 自动化验证、实机验证、用户反馈分别覆盖什么。
6. 数据/安全/兼容性边界，以及如何禁用或回退。

功能状态变化应补充后续记录或更新索引，不把“当时未合入”静默改写成“当时已合入”。
暂存分支也需要记录，但不能只因为文档进入主干，就声称功能已经进入主干。

**公开仓库只提交脱敏结论。** 不提交原始日志、签名 URL、Cookie、代理凭据、
漫画标题/目录清单、数据库、检查点、设备标识、私钥、解密配置、APK 或本机绝对路径。

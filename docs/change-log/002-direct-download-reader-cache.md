# 002 · 普通下载复用阅读缓存

- 日期：2026-09-16。
- 提交：`cc3fbcd85a712ecde7d1f24fe81b2ffdb545840e`。
- 分支：`fix/reuse-reader-cache`；已包含在主干。
- 范围：直接/普通下载，不是 archive 归档包下载。

## 为什么改

用户已经阅读过漫画，图片在阅读缓存中，但点击普通下载仍会重新传输。
阅读使用自定义的页面/图片版本缓存键，旧下载查找主要依赖图片 URL；
新任务又没有充分继承阅读时解析出的元数据，因此两条路径不能可靠定位同一份缓存。

## 改了什么

- 普通下载使用阅读的自定义缓存键，并兼容旧的 URL 缓存键。
- 新建任务时带入阅读元数据；有足够信息时，在重新解析页面/获取图片地址前就
  尝试把缓存字节写入下载目录。
- 原图与重采样版本分开处理；原图地址未知时不拿重采样缓存冒充原图。
- 缓存导出和 SAF 写入完成后才确认单页完成；等待任务数据库写入，串行更新
  画廊完成计数，避免并发完成回调造成状态错乱。
- 停滞检测也计入缓存完成的页面，而不是把“没有网络流量”等同于“没有进度”。
- 启用 `flutter_test`，同步测试所需的锁定依赖；不是一次无关的运行时依赖升级。

## 为什么这样做

优先复制已经存在的有效图片，不把缓存强制搬走或清空，让阅读仍能复用它。
下载文件和任务状态继续通过原有保存流程落地；统一缓存定位，而不是让阅读和
下载各维护一套无法对应的索引。

对原图和图片版本保持保守，避免为了减少请求而悄悄降低用户选择的图片质量。
SAF 写入必须真实成功，不能把“开始写文件”或“收到最后一个进度回调”当作保存完成。

## 验证与后续

该提交记录了当时 **37 项回归测试**，覆盖缓存命中/未命中、图片版本、
重试/取消、SAF 写入及完成顺序。归档下载和既有 SD 卡授权修复未改。

后续实机反馈表明，自动补页仍可能跳过缓存，见 [003](003-retry-cache-and-diagnostics.md)；
URL 缺少 `xres` 造成的缓存键分裂，则在 [007](007-cache-representation-keys.md) 单独修正。

主要代码：`lib/network/api.dart`、`lib/common/controller/download/`、
`lib/common/controller/download_controller.dart`、`lib/store/db/isar_helper.dart`。
